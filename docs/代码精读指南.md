# 代码精读指南（企业级改造版）

> 用法：按站点顺序读，每站 30～60 分钟。每站先看"这一站看什么"，再去读对应代码，
> 最后回答"自测题"。答不上来的题，就是还没吃透的地方。
> 全部 11 站，正常节奏 2～3 天。

## 站 0：先建立全局地图（30 分钟）

**要搞清楚的 3 件事**

1. 服务有哪些进程：FastAPI（API）、Celery worker（后台任务）、Elasticsearch、MySQL、Redis、Ollama。
2. 一次"上传文档"的完整链路：HTTP → 权限校验 → 写 MySQL → 落盘 PDF → 投递 Celery 任务 → worker 解析 → 写 ES → 回写 task 表。
3. 一次"提问"的完整链路：HTTP → 权限校验 → 校验知识库归属 → query 改写 → 向量化 → BM25 + KNN 双路召回 → RRF → 重排 → 组装 Prompt → LLM 流式输出。

**动作**：自己在纸上画这两条链路（先不看代码）。画完再对照 `README.md` 的架构图和 `main.py` 的端点列表。

**自测题**

- 上传接口返回 200 时，解析完成了吗？为什么？
- 用户在浏览器里点"提问"，服务端一共访问了哪些外部组件？

## 站 1：配置与启动（`env_loader.py` / `config.yaml` / `db_api.py:8-58`）

**这一站看什么**

- `env_loader.py:9` — `.env` 是怎么被加载进环境变量的（`os.environ.setdefault` 保证不覆盖真实环境变量）。
- `db_api.py:12` — 为什么在模块导入时就 `load_dotenv()`。
- `db_api.py:17` — `_cfg()` 的取值优先级：环境变量 > yaml > 默认值。
- `db_api.py:30-58` — 双引擎分支：sqlite 与 mysql 各自怎么建 `engine`；MySQL 的 `URL.create`、`charset=utf8mb4`、连接池四个参数。
- `config.yaml` 的 `database` 段 —— 默认引擎、路径、主机、账号。

**自测题**

- 为什么密码不写在 `config.yaml` 而是 `.env`？`.env` 被谁忽略了？
- `pool_pre_ping` 和 `pool_recycle` 分别解决什么问题？
- 为什么 MySQL 连接串要用 `URL.create()` 而不是 f-string 拼接？
- 想把项目切回本地 SQLite，要改哪一行？

## 站 2：数据模型（`db_api.py:60-141`）

**这一站看什么**

- `KnowledgeDatabase` / `KnowledgeDocument`：`owner_id`、`department_id` 为什么存在（租户隔离的依据）。
- `User`：`password_hash` / `role` / `department_id` / `is_active` 各自的作用。
- `Task`：为什么任务状态要落库（可查询、可审计、可做租户过滤）。
- 字段长度（`String(255)`）：MySQL 的 VARCHAR 为什么必须带长度。

**自测题**

- 三张业务表之间是什么关系？（知识库 1—N 文档）
- `Task.task_id` 为什么用字符串而不是自增整数？
- 如果给 `KnowledgeDocument` 加一个 `version` 字段，接下来要做哪几步？（答案指向站 3）

## 站 3：数据库迁移 Alembic（`alembic/env.py` / `alembic/versions/*` / `scripts/migrate_sqlite_to_mysql.py`）

**这一站看什么**

- `alembic/env.py` — 为什么复用 `db_api` 的 `engine` 和 `Base.metadata`；SQLite 的 `render_as_batch`。
- `alembic/versions/c902137a8399_*` — 初始两张表的建表语句（`upgrade` / `downgrade` 各做什么）。
- `alembic/versions/3ac18a7a348b_*` — 新增 `user` 表。
- `alembic/versions/7d3f9edb6177_*` — 新增 `task` 表。
- `scripts/migrate_sqlite_to_mysql.py` — 为什么必须保留原 ID（ES 的 chunk 用 `document_id` / `knowledge_id` 关联）。

**自测题**

- `create_all` 和 Alembic 的本质区别是什么？
- `alembic upgrade head` / `alembic downgrade -1` / `alembic stamp head` 分别什么时候用？
- 为什么这个项目的迁移文件能在 SQLite 和 MySQL 上通用？

## 站 4：认证——"你是谁"（`security.py:52-115` / `auth_routes.py`）

**这一站看什么**

- `security.py:65` `hash_password` / `72` `verify_password` — bcrypt 加盐哈希；为什么不能存明文、为什么不返回"密码错误 vs 用户不存在"。
- `security.py:80` `_create_token` — JWT 的 payload 里放了什么（sub / role / department_id / type / exp / jti）。
- `security.py:103` `decode_token` — 签名校验、过期校验、`type` 校验（防止 refresh token 当 access 用）。
- `auth_routes.py:36` `/v1/auth/login` — OAuth2 表单流程，为什么要用 `OAuth2PasswordRequestForm`。
- `auth_routes.py:50` `/refresh`、`61` `/me`、`71` `/register`。

**自测题**

- access token 和 refresh token 的区别是什么？为什么两者要分开？
- 为什么登录失败时不能提示"用户不存在"？
- Swagger 右上角 Authorize 按钮是谁提供的？它背后调了哪个接口？

## 站 5：授权与多租户——"你能干什么、能看谁的数据"（`security.py:118-176` / `main.py:53-80` / 各端点）

**这一站看什么**

- `security.py:118` `Principal` — 一次请求的身份载体；`department_scope()` 为什么对 admin/system 返回 `None`。
- `security.py:132` `tenant_conditions()` — 生成 `department_id = X` 过滤条件。
- `security.py:140` `_principal_from_token` — 为什么不直接信任 token 里的 role/department，而要回库查。
- `security.py:169` `require_permission()` — 依赖工厂：端点上一行声明需要什么权限。
- `main.py:204` / `258` / `292` / `357` — 四个知识库端点如何挂权限、如何加租户过滤。
- `main.py:746` `/chat` — 为什么先校验知识库归属再检索。

**自测题**

- 401 和 403 的区别？为什么跨部门访问要返回 404 而不是 403？
- 请求体里传 `department_id=99` 为什么无效？
- viewer 为什么能查知识库（200/404）却不能建知识库（403）？
- 只在数据库层做租户过滤够不够？为什么检索层（ES）也要过滤？

## 站 6：上传与异步任务（`main.py:584-700` → `tasks.py` → `task_store.py` / `celery_app.py`）

**这一站看什么**

- `main.py:584` `add_document` — 校验文件名 → 写 DB 行 → 落盘 → 投递任务（对比以前用 `BackgroundTasks` 的写法）。
- `tasks.py:29` `enqueue_parse_document` — 幂等投递：已有进行中任务就不重复投。
- `tasks.py:47` `parse_document` — 回查文档元数据 → `mark_started` → 调 `extract_content` → 成功/失败/重试分别怎么处理。
- `task_store.py:23-131` — 状态机 `pending → started → success / failure` 的落库实现。
- `celery_app.py` — `acks_late`、`reject_on_worker_lost`、`visibility_timeout=300`、`prefetch_multiplier=1` 各自的作用。
- `main.py:552` `/v1/task`、`568` `/v1/document/status` — 状态怎么查、怎么带租户过滤。

**自测题**

- 为什么任务只传 `document_id`，而不是把所有字段都传过去？
- worker 执行到一半被杀，任务会怎样？`acks_late` 和 `visibility_timeout` 分别起什么作用？
- 任务重跑会不会在 ES 里写重复数据？为什么？
- `extract_content` 内部有重试，Celery 层也有重试，为什么要这样分层？会不会重试太多次？

## 站 7：检索链路与 ES（`rag_api.py:373-540` / `es_api.py:33-115`）

**这一站看什么**

- `es_api.py:33` `init_es` — 两个索引（`chunk_info` / `document_meta`）的 mapping，含 `department_id` 字段。
- `rag_api.py:197` `_extract_pdf_content` — 解析 → 分块 → 向量化 → 写 ES（注意写入时的 `owner_id` / `department_id`）。
- `rag_api.py:373` `_word_search` / `392` `_vector_search` — 两路召回，各自的 filter 里都有 `knowledge_id` + `department_id`。
- `rag_api.py:412` `query_document` — 双路并行召回 → RRF 融合 → 重排 → 取 top-k。
- `rag_api.py:508` `_retrieve_context` — 组装 Prompt；`598` `query_rewrite` — 多轮指代改写。
- `main.py:745` `/chat` → `_stream_tokens` — SSE 事件协议（debug / token / done）。

**自测题**

- 为什么要"关键词检索 + 向量检索"两路，而不是只用一路？
- RRF 用排名而不是分数融合，好处是什么？
- 如果检索时不加 `department_id` 过滤，会发生什么？（提示：数据泄露方向）
- 用户问"它的作者是谁"，`query_rewrite` 起了什么作用？

## 站 8：跨存储一致性与级联删除（`main.py:292-356` / `501-552` / `es_api.py:116-160` / `utils.py`）

**这一站看什么**

- 删除的顺序为什么钉死为「ES 先删（失败阻断）→ 物理文件删（失败告警）→ 数据库最后删（同事务）」。
- `es_api.py:116` `_assert_no_delete_failures` — 为什么 `delete_by_query` 还要检查 `version_conflicts` / `failures`。
- `utils.py` `safe_remove_file` — 为什么删文件失败只告警。
- `delete_document` / `delete_knowledge_base` 里"先快照字段再 commit"的原因（`ObjectDeletedError`）。

**自测题**

- 如果先删数据库、再删 ES，中途 ES 挂了，会留下什么问题？
- 删知识库和删文档的范围有什么不同？怎么保证不误删其他库？
- 为什么无法用一个数据库事务把 MySQL + ES + 磁盘包起来？企业里怎么最终解决？（提示：发件箱/事件驱动）

## 站 9：日志与可观测现状（`logging_config.py` / `main.py:166-202` / `rag_api.py` 计时）

**这一站看什么**

- `logging_config.py:11` `RequestIdFilter` — 用 `contextvars` 把 request_id 注入每条日志。
- `logging_config.py:23` `setup_logging` — 控制台 + 5MB 轮转文件。
- `main.py:184` `log_requests` 中间件 — 为每个请求生成 request_id、记录方法/路径/状态码/耗时。
- `main.py:166` 统一错误信封（request_id / response_code / response_msg / process_status）。
- `rag_api.py` 的检索四段计时（改写/向量/召回/重排）日志。

**自测题**

- 为什么用 `ContextVar` 而不是全局变量保存 request_id？
- 现在能在一条日志里同时看到"哪个请求 + 哪一步慢"吗？怎么做到的？
- 线上想知道"最近 5 分钟的 P95 延迟"，光靠这套日志为什么很难？（答案指向 E 阶段）

## 站 10：测试与 CI（`test/conftest.py` / `pytest.ini` / `.github/workflows/test.yml` / `requirements-ci.txt`）

## 读完之后的检验标准

能不看代码回答出下面这些，就说明你真的吃透了：

1. 画出一张包含 API / MySQL / ES / Redis / worker / Ollama 的架构图，并标出一次上传和一次问答的数据流；
2. 说出至少 3 个"我们踩过的坑"以及对应的设计决策（如 MySQL VARCHAR 长度、Celery visibility_timeout、跨租户 404 而非 403）；
3. 讲清楚哪些东西是"进程内"、哪些是"跨进程"，以及跨进程通信靠什么（HTTP、Redis 队列、数据库）。
