## Part A：新增代码里用到的库（速查）

### 第三方库

| 库 | 作用 | 出现在哪 | 少了它会怎样 |
|---|---|---|---|
| `sqlalchemy` | ORM + 连接池 + 引擎抽象；`create_engine` / `URL` / `Column` / `sessionmaker` | db_api.py、task_store.py、迁移脚本 | 无法连数据库、无法定义模型 |
| `pymysql` | MySQL 的 DBAPI 驱动（`mysql+pymysql://` 里的 pymysql） | 由 SQLAlchemy 间接调用 | 连 MySQL 时报 `No module named 'pymysql'` |
| `cryptography` | MySQL 8 默认认证方式 caching_sha2_password 需要它 | pymysql 间接使用 | 连 MySQL 可能报认证错误 |
| `alembic` | 表结构版本管理（`alembic upgrade/downgrade/revision`） | alembic/env.py、versions/* | 只能靠手写 SQL 改表，无法回滚 |
| `PyYAML` (`yaml`) | 读 config.yaml | db_api.py、security.py、迁移脚本 | 配置读不出来 |
| `fastapi` | Web 框架；`APIRouter` / `Depends` / `HTTPException` / `Security` | main.py、auth_routes.py、security.py | 没有 API |
| `fastapi.security` | `OAuth2PasswordBearer`（Bearer 认证 + Swagger Authorize）、`OAuth2PasswordRequestForm`（表单登录）、`APIKeyHeader`（X-API-Key） | security.py、auth_routes.py | 认证流程与 Swagger 授权按钮失效 |
| `pydantic` | 请求/响应模型的校验与序列化（`BaseModel` / `Field`） | router_schemas.py | 参数没有类型校验 |
| `bcrypt` | 密码加盐哈希 | security.py | 无法安全存密码 |
| `PyJWT` (`jwt`) | 签发/校验 JWT | security.py | 无法做无状态登录态 |
| `celery` | 异步任务框架（连接 Redis、调度 worker、重试） | celery_app.py、tasks.py | 回到进程内任务，重启即丢 |
| `redis` | Celery 的 broker/backend 客户端（由 kombu 使用，代码里不直接 import） | 通过 `RAG_REDIS_URL` 间接 | 任务发不出去 |
| `pytest` | 测试框架 | test/* | 无法自动化回归 |
| `httpx` + `starlette.TestClient` | 在进程内模拟 HTTP 请求 | test/test_auth_api.py | API 级测试无法进行 |
| `torch` / `transformers` / `sentence-transformers` | BGE embedding / rerank 模型（**项目原有**） | rag_api.py | 解析与检索无法向量化；也是 worker 启动慢、吃 2GB 内存的原因 |
| `elasticsearch` / `pdfplumber` / `openai` | ES 客户端 / PDF 解析 / LLM 调用（**项目原有**） | es_api.py、rag_api.py | 对应功能失效 |

## Part B：12 个最容易"读过去但没真懂"的细节

1. **`os.environ.setdefault`**（env_loader.py）：`.env` 只在环境变量不存在时写入 → 所以"真实环境变量 > .env"，
   测试才能在 import 前强制把引擎切到临时 SQLite。
2. **import 即副作用**：`db_api.py` 在模块导入时就 `load_dotenv()` + 建 `engine`，
   所以"谁先 import、环境变量什么时候设置"会决定连哪个库。
3. **`URL.create()` 做转义**：密码含 `@`、`#` 也不会拼坏连接串；SQLAlchemy 打印 URL 时自动把密码显示成 `***`。
4. **`String(255)` 的长度**：SQLite 不在意，MySQL 的 VARCHAR 必须给长度，否则建表报错——这是切库时最典型的坑。
5. **`pool_pre_ping` / `pool_recycle=3600`**：解决"连接被 MySQL 的 `wait_timeout` 掐断后拿到死连接"的问题。
6. **bcrypt 的 72 字节上限**：超长直接拒绝（避免静默截断）；`verify_password` 捕获异常返回 False（避免非法哈希导致 500）。
7. **JWT 的 `type` 字段**：access 与 refresh 不能混用；`decode_token(token, "access")` 会拒绝 refresh token。
8. **`_principal_from_token` 每次回库查用户**：token 里的 role/department 只是"签发时的快照"，
   真正生效的是数据库里的最新值——用户被禁用或调岗立即生效。
9. **`require_permission()` 是闭包工厂**：`Depends(require_permission("kb:read"))` 每个请求都会执行一次；
   403 在依赖层抛出，再被 `http_exception_handler` 包装成统一错误信封。
10. **`tenant_conditions()` 用 `*` 展开**：admin/system 返回空列表 → 相当于不加过滤；普通用户返回 `[department_id == X]`。
11. **Celery 的 `acks_late` + `visibility_timeout`**：前者保证"执行完才确认"，后者决定 worker 崩溃后多久重新投递（默认 1 小时，我们改成 300 秒）。
12. **幂等靠什么**：ES 的 `_id` 是确定性拼出来的（`doc_{document_id}_page_{n}`），所以任务重跑是"覆盖"而不是"写两份"；
    任务投递的幂等则靠 `find_active_task()`（有 pending/started 就复用）。

## Part D：3 个安全实验（比答题更能检验理解）

> 都在本地测试数据上做，做完记得改回来。

1. **切库实验**：把 `.env` 里 `RAG_DB_ENGINE` 改成 `sqlite` → 跑 `python -m alembic current`，
   观察日志从 `MySQLImpl` 变成 `SQLiteImpl` → 理解环境变量优先级。
2. **越权实验**：用 viewer2 的 token 调 `/chat` 访问 admin 部门的知识库 → 观察 404；
   再用 viewer2 调 `POST /v1/knowledge_base` → 观察 403。对比两者的差别。
3. **失败任务实验**（需要 worker 在跑）：
   `python -c "from tasks import parse_document; parse_document.apply(args=[999999, 'doc-999999-test'])"`
   → 查 `task` 表，应看到 `status=failure` 且 `error_msg` 是"文档记录不存在" → 理解任务失败是怎么被记录的。

## Part E：自评等级（对每个功能给自己打分）

| 等级 | 标准 |
|---|---|
| L1 能背 | 知道这个功能叫什么、用了什么库 |
| L2 能解释 | 能说清"解决什么问题、为什么这么设计" |
| L3 能改 | 能独立加一个字段/改一个配置/加一个接口 |
| L4 能排错 | 出故障时知道先看哪、怎么定位、怎么恢复 |

**面试至少要到 L3，最好有一个功能到 L4。** 比如 Celery：你亲手处理过 `unacked` 卡住 + 重投，
这就是 L4 的经历，一定要在心里过一遍"当时怎么判断、怎么恢复"，面试官很吃这套。
