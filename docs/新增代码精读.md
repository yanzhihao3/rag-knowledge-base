# 新增/改动代码精读（6 个企业级功能）

> 只覆盖我这几轮**新增和修改**的代码，不包含项目原有的 RAG 检索逻辑（那部分见 `docs/代码精读指南.md`）。

## 功能 1：MySQL 双引擎（提交 `3e7bc13`、`e3b1210`）

**解决什么问题**：原来只支持 SQLite，且连接串是拼字符串；要能切 MySQL，同时不破坏 SQLite。

| 文件 | 改动 |
|---|---|
| `db_api.py` | 新增 `_cfg()` 取值优先级；MySQL 分支用 `URL.create`；连接池参数；`String(n)` 补长度 |
| `main.py` | `_is_retryable_db_error()`：按引擎区分重试（MySQL 只重试 1205/1213） |
| `scripts/migrate_sqlite_to_mysql.py` | 新增：一次性数据迁移，**保留原主键 ID** |
| `config.yaml` / `config.docker.yaml` | database 段补 port/username/password/database |
| `requirements.txt` | 补 `sqlalchemy`、`pymysql`、`cryptography` |
| `.env` / `.env.example` / `env_loader.py` | 密码走环境变量/`.env`，不进仓库 |

**关键代码位置**

- `db_api.py:8、12` — `load_dotenv()` 在模块导入时执行
- `db_api.py:17` — `_cfg(db_config, key, env_name, default, cast)`：环境变量 > yaml > 默认值
- `db_api.py:30-58` — sqlite 分支与 mysql 分支；`URL.create(drivername="mysql+pymysql", ...)`；`pool_pre_ping` / `pool_recycle` / `pool_size` / `max_overflow` / `charset=utf8mb4`
- `db_api.py:60-141` — 所有 `String(255)` 等长度声明（MySQL 硬性要求）
- `main.py:53-71` — `_is_retryable_db_error()`，MySQL 用 `exc.orig.args[0]` 判断死锁/锁超时
- `scripts/migrate_sqlite_to_mysql.py` — 逐表拷贝；设置 `AUTO_INCREMENT = max(id)+1`

**自测题**

1. 为什么不写成 `f"{db_type}://..."`？密码里含 `@` 会怎样？
2. 为什么迁移脚本必须保留原 ID？不保留会破坏什么？
3. SQLite 的 `String` 不写长度为什么没事，MySQL 不行？

## 功能 2：Alembic 表结构版本管理（提交 `c036c69`）

**解决什么问题**：`create_all` 只能建新表、不能改已有表，无法回滚、无法多环境一致。

| 文件 | 改动 |
|---|---|
| `alembic.ini` / `alembic/env.py` / `alembic/script.py.mako` | 新增：迁移框架配置 |
| `alembic/versions/c902137a8399_init_knowledge_tables.py` | 基线：两张业务表 |
| `db_api.py` | 删掉 `Base.metadata.create_all(engine)` |

**关键代码位置**

- `alembic/env.py` — 复用 `db_api.engine` 与 `Base.metadata`（所以同一套迁移能跑 SQLite 和 MySQL）；`render_as_batch` 处理 SQLite 改列
- `alembic/versions/c902137a8399_*.py` — `upgrade()` 建表、`downgrade()` 删表
- 常用命令：`alembic upgrade head` / `downgrade -1` / `current` / `stamp head` / `revision --autogenerate -m "..."`

**自测题**

1. `create_all` 和 Alembic 的本质区别？
2. 存量数据库第一次接入 Alembic 为什么要用 `stamp head` 而不是 `upgrade head`？
3. 改了模型后，生成迁移并在两个库上生效，完整命令是什么？

## 功能 3：JWT 认证（提交 `5a64880`）

**解决什么问题**：原来只有一个静态 API Key，系统不知道"你是谁"，也没法做权限和租户。

| 文件 | 改动 |
|---|---|
| `security.py` | 新增：bcrypt 哈希、JWT 签发/校验、`Principal`、权限依赖 |
| `auth_routes.py` | 新增：`/v1/auth/login`、`/refresh`、`/me`、`/register` |
| `db_api.py` | 新增 `User` 表 |
| `alembic/versions/3ac18a7a348b_add_user_table.py` | 新增迁移 |
| `scripts/create_user.py` | 新增：初始管理员由脚本创建 |
| `router_schemas.py` | 新增 `RegisterRequest` / `TokenResponse` / `UserResponse` |
| `main.py` | 移除全局 API Key 依赖，改为端点级权限依赖 |

**关键代码位置**

- `security.py:65、72` — bcrypt 加盐哈希与校验；72 字节上限
- `security.py:80` — JWT payload：`sub / role / department_id / type / jti / iat / exp`
- `security.py:103` — `decode_token()`：签名、过期、类型三重校验
- `security.py:156` — `get_current_principal()`：Bearer JWT 或 X-API-Key，二者取其一
- `auth_routes.py:36` — 登录：统一错误信息防用户名枚举；记录 `last_login_dt`
- `auth_routes.py:71` — `register` 需要 `user:manage` 权限

**自测题**

1. access token 与 refresh token 为什么要分开？`type` 字段防的是什么攻击？
2. 为什么每次请求都要回数据库查用户，而不是直接用 token 里的 role？
3. 登录失败为什么返回同一句"用户名或密码错误"？

## 功能 4：RBAC 授权 + 多租户隔离（提交 `5a64880`）

**解决什么问题**：不同角色能力不同；不同部门的数据必须互相看不见，且检索侧也不能绕过。

| 文件 | 改动 |
|---|---|
| `security.py` | `ROLE_PERMISSIONS` 权限矩阵；`Principal.department_scope()`；`tenant_conditions()` |
| `main.py` | 每个业务端点挂 `require_permission(...)`、加 `tenant_conditions(...)` 过滤；创建时归属由服务端写入 |
| `rag_api.py` | `_word_search` / `_vector_search` / `query_document` / `_retrieve_context` 逐层透传 `department_id`，写 ES 时带上真实 owner/department |
| `router_schemas.py` | `KnowledgeRequest` 删除客户端可传的 owner/department 字段 |

**关键代码位置**

- `security.py:38-50` — `ROLE_PERMISSIONS`：admin / editor / viewer / system
- `security.py:118-137` — `Principal`、`department_scope()`、`tenant_conditions()`
- `security.py:169` — `require_permission()` 依赖工厂（403 从这里抛出）
- `main.py:53-71`、`74-78` — 重试判断与 `_is_visible()`（任务可见性）
- `main.py:204、258、292、357` — 知识库四个端点的权限 + 过滤写法
- `main.py:584` 起 `add_document` — KB 归属校验、写入时用服务端身份
- `main.py:746` `/chat` — 先校验知识库归属，再带 `department_scope()` 进检索
- `rag_api.py:373、392` — 两路检索的 filter 都带 `department_id`
- `rag_api.py:197` — 写 ES 时写入真实 `owner_id` / `department_id`

**自测题**

1. viewer 查别的部门知识库为什么是 404 而不是 403？
2. 只在 MySQL 层过滤、ES 层不过滤，会有什么后果？
3. 请求体里传 `department_id=99` 为什么没生效？
4. admin、system（X-API-Key）为什么可以跨部门？这个设计有什么风险？

## 功能 5：Celery + Redis 异步任务（提交 `5172728`、`c112176`）

**解决什么问题**：原来用 `BackgroundTasks`，任务在 API 进程内，服务重启/崩溃就丢。

| 文件 | 改动 |
|---|---|
| `celery_app.py` | 新增：Celery 实例与可靠性配置 |
| `tasks.py` | 新增：`enqueue_parse_document()`（幂等投递）、`parse_document()`（状态回写、分层重试） |
| `task_store.py` | 新增：task 表读写与状态机 |
| `env_loader.py` | 新增：`.env` 加载抽成公共模块（db_api 与 celery_app 共用） |
| `db_api.py` | 新增 `Task` 表 |
| `alembic/versions/7d3f9edb6177_add_task_table.py` | 新增迁移 |
| `main.py` | 上传改为投递任务；新增 `/v1/task`、`/v1/document/status`；删除时清理任务 |
| `docker-compose.yml` / `.env.example` | 新增 Redis 服务与 `RAG_REDIS_URL` |
| `scripts/requeue_document.py` | 新增：卡住任务的一键重投 |
| `test/test_task_store.py` | 新增：状态流转测试 |

**关键代码位置**

- `celery_app.py` — `acks_late`、`reject_on_worker_lost`、`visibility_timeout=300`、`prefetch_multiplier=1`
- `tasks.py:29` — 幂等投递：`find_active_task()` 命中就复用，不重复投
- `tasks.py:47` — 只传 `document_id`，worker 自己回查元数据；成功/失败/重试三条分支
- `task_store.py:23-131` — `new_task_id` / `create_task` / `find_active_task` / `mark_started|retrying|success|failure`
- `main.py:584-660` — 上传：写 DB → 落盘 → `enqueue_parse_document`
- `main.py:552、568` — 任务状态查询接口（带租户过滤）
- `scripts/requeue_document.py` — 标记旧任务失败 → 重新投递

**自测题**

1. 为什么任务函数只接收 `document_id`？
2. worker 被强杀，任务为什么没丢？`acks_late` 与 `visibility_timeout` 各管什么？
3. 同一个文档重复上传/重复投递，会不会在 ES 里写两份数据？为什么？
4. `extract_content` 内部重试 3 次，Celery 层又重试 2 次，一共最多几次？会不会失控？

## 功能 6：测试隔离 + CI（提交 `99dd4a1`）+ 仓库清理（提交 `dfe64c1`、`3417f5b`）

**解决什么问题**：测试会误删开发库数据；CI 跑的用例和依赖不对；旧的文件版状态机已被 task 表取代，属于僵尸代码。

| 文件 | 改动 |
|---|---|
| `test/conftest.py` | 测试强制用临时 SQLite；`RAG_SKIP_INTEGRATION=1` 跳过重型测试 |
| `requirements-ci.txt` / `.github/workflows/test.yml` | CI 只装轻量依赖、只跑轻量测试 |
| `pytest.ini` | 注册 `integration` 标记 |
| `utils.py` | 删除 `SqliteStateStore` / `TaskStateMachine`（旧状态机） |
| `main.py` / `rag_api.py` | 移除旧状态机调用 |
| `test/test_state_machine.py` | 删除（11 个针对旧实现的测试） |
| `LICENSE` / `docs/images/benchmark.png` | 新增协议；截图归档 |

**关键代码位置**

- `test/conftest.py` — 在任何测试 import 之前设置 `RAG_DB_ENGINE=sqlite` + 临时路径（利用"真实环境变量优先级最高"）
- `test/conftest.py` 的 `collect_ignore` — CI 模式跳过 8 个重型测试文件
- `.github/workflows/test.yml` — `pip install -r requirements-ci.txt` → `pytest`
- `utils.py` — 现在只剩 `safe_remove_file` 和 `with_retry`

**自测题**

1. 测试为什么不直接连 MySQL？不隔离会出什么事？
2. `if __name__ == "__main__"` 和 `pytest` 两种运行方式，环境变量分别来自哪里？
3. 为什么 `requirements-ci.txt` 里没有 torch？
