## 六、决策记录（为什么这么选）

| 决策 | 理由 |
|---|---|
| **不换 LangChain** | 定制逻辑全在检索侧（租户过滤、RRF、rerank、幂等重灌）；只有 ES 一家后端，统一接口无收益；换框架要重写还未必跑得过现有指标 |
| **父子块默认关闭** | 实测命中率打平（仅子块 90%、答案页 94%），只多救回 1 道题；成本是上下文 +23%。理论上有 17 道题"该赢"，但你的页平均只有 1.6 块 → 收益上限低。**等分块粒度变细（4-5 块/页）再回来看** |
| **排除 MinerU** | 模型 3-5GB + 建议 GPU + 240 页可能几十分钟；而本地 OCR 只要 200MB、15-20 分钟、零成本，且已验证表格能还原 |
| **pymupdf4llm 待做** | 验证通过（标题/段落/断行三个信号全满足），但**它不解决图片**，所以应该和 OCR 一起做，而不是单独换 |
| **语义分块保留** | 净收益小（融合 +1 道题），但修掉了碎片块（64→18），且是"按句边界切"的正确基础 |
